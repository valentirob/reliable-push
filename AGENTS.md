# AGENTS.md — reliable-push

This is the canonical, LLM-agnostic context file for this repository. It is read
natively by Google Antigravity (and other tools that follow the AGENTS.md
convention). Claude Code reads it through `CLAUDE.md`. Keep tool-specific files
thin and put shared knowledge **here** or in the files linked below.

## Project in one paragraph

reliable-push is an MIT-licensed add-on for teams that already send push
notifications (FCM / APNs). It tracks whether each push was **delivered** and
**read** on the device and, if a per-notification policy is not satisfied
within N minutes, triggers a **fallback** by calling a configurable,
HMAC-signed webhook (`userId`, message, `trackingId`) that routes to SMS,
email or any other channel. It runs as a sidecar: the existing backend keeps
sending pushes itself.

## Working agreement (any LLM, any human)

- Branching is **gitflow** (see rule). Never commit directly to `main`.
- Test first: no production code without a failing test that requires it.
- Never claim "done" without running the verification commands and reading their output.
- A change is done only when the docs, the diagrams (`docs/overview.md`, the at-a-glance picture) and `docs/presentation.html` match it (see the `docs-sync` rule).
- Keep files small and single-purpose; follow the existing package structure.
- English for code, comments, commits and docs.
- No secrets in the repo. Use `.env.example` / `application-example.yml` with placeholders.
- End every session with the `session-handoff` skill so another agent, on another machine and another LLM, can continue.

## Maintainer agreement (how this repository is run)

The project has one maintainer. Agents working for them follow these rules too:

- **Start of a session:** read `docs/STATUS.md` (newest entry first), its open questions and `docs/TODO.md`, and remind
  the maintainer of TODO section 1 (real APNs with the locked-device check, real FCM, Maven Central).
- **Language:** talk to the maintainer in Italian; everything in the repository stays in English.
- **Design conversations:** ask the questions that change the design, make counter-proposals, and say plainly when an
  approach stays invasive or contradicts an earlier decision. Agreeing by default has cost a redesign before (cycle 6).
  New work follows `plan-feature`: approved spec, then plan, then code.
- **Merging:** a finished `feature/*` or `bugfix/*` branch (tests green, `review-loop` clean, docs in sync) is merged
  into `develop` with `--no-ff` and pushed, without a pull request and without asking. A release happens only when the
  maintainer asks (`release` skill); nobody else pushes to `main`.
- **Commits:** Conventional Commits; a tool may add its own attribution trailer (Claude Code adds `Co-Authored-By`).
- **Never, without the maintainer:** install software; restart or resize the Docker VM (Colima); create accounts,
  sign in or enter credentials; create, print, log or commit the Firebase and APNs files (the maintainer places them,
  git-ignored: see `docs/testing.md`); install Xcode or accept its licences; delete remote branches that are not
  merged.

## Pitfalls seen in earlier sessions

- Several agents in one checkout: never `git stash`, `git checkout -- .` or `git add -A`; stage by path. A stash once
  hid another agent's uncommitted work.
- `gh run list --commit` needs the full SHA; a short one matches nothing and a wait loop never ends.
- macOS `sed -i` differs from GNU `sed -i`; prefer a small script for multi-file edits. In zsh, quote words that start
  with `=` (`echo "===="`).
- The iOS size gate (`ios/scripts/size.sh`) moves in 16 KB pages and has about 240 bytes left: read TODO 4.11 before
  adding iOS code.
- The Android emulator E2E `offline-delivery-is-sent-when-network-returns` is flaky in a full run (the emulator's
  JobScheduler); re-run it alone before suspecting the SDK.

## Commands

Environment: JDK 21 and Docker (Testcontainers; the image tests build the container image). On a Mac with Homebrew OpenJDK 21
and Colima, export `JAVA_HOME=/opt/homebrew/opt/openjdk@21`, put its `bin` first on `PATH`, and set
`DOCKER_HOST=unix://$HOME/.colima/default/docker.sock` and `TESTCONTAINERS_DOCKER_SOCKET_OVERRIDE=/var/run/docker.sock` before
running the Maven commands; on Linux and Windows see `docs/getting-started.md` §0. Details: `docs/testing.md`.

| Task | Command |
|---|---|
| Backend build + unit + integration tests + coverage gate (80% line) | `cd backend && ./mvnw -B verify` |
| Backend container image + image tests | `cd backend && ./mvnw -B verify -Pimage` |

| Backend one integration test | `cd backend && ./mvnw -B verify -Dit.test=NotificationApiIT -Dtest=NoSuchTest -Dsurefire.failIfNoSpecifiedTests=false -Djacoco.skip=true` |

| Java sender client build + tests (run from the repo root) | `./mvnw -B -pl client-java verify` |
| Payload jar build + tests (JDK 21 locally; CI also runs the tests on a Java 8 JVM with `-Djvm=<path to java 8>`) | `./mvnw -B -pl payload-java verify` |
